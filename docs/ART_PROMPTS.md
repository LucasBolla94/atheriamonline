# Atheriam — Original art production record

Date: 2026-09-12. Tool: built-in imagegen (not CLI). No commercial-game images were supplied as references. These assets were generated for this project; they are not a third-party stock pack. The original PNGs remain in `apps/client/public/art/*-source.png`; the runtime uses the small atlases exported by `scripts/bake-art.mjs`.

## Resident source

Use case: stylized-concept. Create a production pixel-art animated sprite sheet for an original medieval social browser game, Atheriam. Transparent PNG background, no text, no labels, no grid lines. Image exactly 1536x1024, organized in exactly 6 equal columns and 4 equal rows, cells 256x256. Every cell contains the SAME small human adult villager, gender-neutral, warm medium skin, short dark brown hair, teal blue simple tunic with leather belt, dark brown trousers and boots. Charming simple chunky pixel art, clean dark colored outline, 2 shades per material, no tiny detail, no antialiasing, apparent source character resolution 24x32 enlarged nearest-neighbor. Each sprite centered horizontally at x=128 of its cell, feet bottom aligned y=224 of its cell. Figure width about112 height160 actual pixels (fits comfortably with transparent padding). Rows are SOUTH/front facing, WEST/left facing, EAST/right facing, NORTH/back facing respectively. Each row is a continuous 6-frame WALK CYCLE: contact left foot, down, passing, contact right foot, down, passing. Arms swing opposite feet, stable head and proportions. The standing central body and feet positions stay consistent across all frames. All 24 sprites must be complete, separate, same size, correctly aligned on regular grid. No shadows on background. Original human design, no references to existing commercial games. Actual transparency, not a drawn checkerboard. Six columns, four rows, 24 sprites total. Strong priority animation consistency and simple readable silhouettes.

The background-removal request did not produce usable transparency. A second edit changed the background to uniform magenta #FF00FF. The loader's chroma-key stage makes those pixels transparent and aligns the figures to a common foot anchor. Two edited resident variants preserve the original sheet layout: an auburn ponytail/coral tunic resident, and a dark-skinned curly-haired resident with a golden tunic and cream apron. Three additional curated dyes are produced by the same atlas pipeline. These are six complete looks, not independently mixable body/clothing layers.

## Town objects

Production game object sprite atlas, original Atheriam medieval town, simple clean chunky pixel art, warm welcoming palette of sage green, golden wood, sandstone and terracotta. Exactly 4 columns and 3 rows on a 1536x1024 image: each cell 384 pixels wide, 341 pixels tall approximately. All objects are isolated against uniform bright magenta #FF00FF for chroma key, with no ground, no cast shadows outside object, no grid, no words, no decorative frame. Objects centered inside each cell with wide empty margins, complete unclipped sprites occupying about 65 percent cell width/height. Consistent RPG top-down 3/4 view with visible front and top, square grid NOT isometric, light upper-left, crisp dark colored pixel outlines, minimal details. Row1: round leafy green deciduous tree with visible trunk; small covered stone village well with terracotta pitched roof; wooden market stall with striped cream and coral awning and vegetables; compact cottage with terracotta roof, cream plaster and brown timber facade and central door. Row2: wooden three-legged oak stool; woven rectangular rush floor mat; small clay oil lamp with golden flame; wooden long table seen from above/front. Row3: red wool rug; copper cloak brooch; smooth river stone; brass hand bell. Exactly these 12 sprites in that order, no duplicates. Simple game-ready pixel art each designed as about 48-64 native pixels enlarged crisply. Whole sprites must not cross cell boundaries.

A follow-up edit replaced the background with uniform magenta #FF00FF for the same chroma-key pipeline. Objects are registered by stable IDs rather than display names.

## Regeneration

Start the client dev server on port 5173, then run `node scripts/bake-art.mjs` from the repository root. It exports six resident atlases, six portrait images, one object atlas and twelve item/object previews. This step needs Playwright Chromium. Run it only when source art changes; it is not part of every player login or production startup. Inspect the images, then run the game's browser checks before publishing.
